# 节点图执行器 GraphExecutor 使用说明

`GraphExecutor` 挂在场景 GameObject 上，负责把 `BaseNodeGraph` 跑起来。
一次执行 = **一条链（Run）**：从某个起点沿节点输出一路走到底。

> 本文档专门说明执行器的枚举、触发策略、并发模型与配置方式，改配置前请对照阅读。

---

## 一、总体模型：多链并发

- **每条链独立**：从起点出发各走各的，`Wait`/`WaitUntil`/`ConditionWait` 互不拖累；
- **互不打断**：一条链运行中，其他起点照常启动，不会被掐掉；
- **独立游标**：每条链有自己的"当前节点 / 执行轮数 / 排队标记"（编辑器运行高亮可同时显示多条链）；
- **共享图变量**：并发链共用同一份 `VariableBundle`。**需要合作就共用变量，需要独立就各自新建变量**；
- **同一起点再触发**：由触发策略决定（见下文第三节），不同起点之间永远互不影响。

```
事件A → 入口A ── 链A（独立协程，互不打断）
事件B → 入口B ── 链B（独立协程）
事件C → 入口C ── 链C（独立协程）
```

---

## 二、执行模式（GraphExecutionMode）

决定 `Execute()`（以及 `autoExecute`）解析哪个起点。

| 枚举 | 起点 | 说明 |
|------|------|------|
| `Default` | 图的 `startNode` | 从 StartNode 执行，图里必须有它 |
| `Entry` | 下拉选择的入口节点（`entryIdentifier`） | 从「基本/入口」节点执行 |

> 入口节点用**标识符（Identifier）**寻址；下拉选择入口时编辑器会回填标识符，标识符改名后自动修正。

---

## 三、触发策略（GraphExecutionTriggerPolicy）

**同一起点**正在运行、又收到一次触发时的行为。**不同起点各自独立，不受此策略影响。**

| 枚举 | 行为 | 典型用途 |
|------|------|----------|
| `Restart`（默认） | 停掉该起点的当前链，从起点整条重跑 | 互斥路线：触发 = 取消当前动作改跑新路线 |
| `IgnoreWhileRunning` | 该起点的链运行中，忽略重复触发 | 事件防抖：同一段剧情只播一次 |
| `Queue` | 该起点的链运行中，标记"排队一次"；当前链跑完后自动再跑一轮 | 需要"跑完补跑"的计数器/门闩场景 |

注意事项：

- **`Queue` 只对会自然结束的链有意义**（`executeCount > 0`）。无限链永远跑不完，排队不会执行；
- `Restart` 停链发生在帧边界：`StopCoroutine` 后立即启动新链，两条链不会重叠同一帧执行节点。

---

## 四、入口事件订阅（EntryEventSubscribeMode）

配合 `GraphEvent` 事件总线使用（按钮 `GraphEventEmitter.Emit()`、碰撞 `CollisionEventEmitter`、或 C# `GraphEvent.Trigger`）。

| 枚举 | 行为 |
|------|------|
| `Off` | 不订阅事件，只靠 `autoExecute` / C# 调用执行 |
| `CurrentEntry` | 只订阅**自己入口**（`entryIdentifier`）的事件；事件标识不匹配直接忽略 |
| `AllEntries` | 订阅图内**所有入口**的事件；触发时按事件标识解析对应入口并**并发执行**（互不打断） |

使用步骤（`AllEntries` / `CurrentEntry` 通用）：

1. 图上添加「基本/入口」节点，标识符填事件名（如 `OK路线`）；
2. 执行器：执行模式 = `Entry`，下拉选择该入口；
3. 执行器：入口事件订阅 = `AllEntries`（或 `CurrentEntry`）；
4. 触发源发出相同 `eventId` → 执行器按事件标识找到对应入口启动链。

三者对比如下：

| 场景 | 推荐 |
|------|------|
| 一个执行器只管一条路线 | `CurrentEntry` |
| 一个执行器管多条路线（各自并发） | `AllEntries` |
| 想多执行器各管各的 | 每执行器一个图 + `CurrentEntry` |

---

## 五、字段一览

| 字段 | 说明 |
|------|------|
| `nodeGraph` | 要执行的节点图资产 |
| `autoExecute` | 启动时自动执行一次（按执行模式解析的起点） |
| `executeInterval` | 每条链**每轮之间**的间隔秒数 |
| `executeCount` | 每条链的执行轮数上限（0 = 无限执行） |
| `executionMode` | 见第二节 |
| `entryIdentifier` | 入口标识符 / GUID（下拉选择后自动回填） |
| `triggerPolicy` | 同一起点重复触发策略，见第三节 |
| `entryEventSubscribe` | 入口事件订阅模式，见第四节 |

---

## 六、常见配置示例

**单路线定时播**：`Default` + `autoExecute` + 设 `executeInterval` / `executeCount`。

**多路线事件驱动（一个执行器）**：图里放多个入口（标识符 = 事件名）；
执行器：`Entry` + 任选一个入口 + 入口事件订阅 = `AllEntries`。
按钮A发 `OK路线`、按钮B发 `Cancel路线` → 各自入口并发执行，互不打断。

**互斥路线（按 A 打断当前 A）**：同一起点触发策略 = `Restart`。

**事件防抖（重复点击只播一次）**：触发策略 = `IgnoreWhileRunning`。

**动画/移动接续不互相打断**：不同入口各跑各的链（天然并发，无需额外配置）；
若两条链要协调节奏，共用同一组图变量做条件（`等待条件` 节点）。

---

## 七、调试

- **运行高亮**：Play 模式下 `NodeRunHighlight` 同时高亮**所有运行中链**的当前节点；
  链停在 `等待/等待条件` 节点时高亮停留，方便确认并发状态；
- **日志分级**：`Tools/节点系统/日志级别` 切 `Info` / `Verbose` 查看执行、事件、忽略/排队日志；
- **触发日志**：`IgnoreWhileRunning` 和 `Queue` 命中时都有 Info 日志，写明是哪个起点、什么动作。

---

## 八、与旧版（单链）行为差异

| 项目 | 旧版（单链） | 现在（多链并发） |
|------|--------------|------------------|
| 多个入口触发 | 后触发覆盖前一个（可能被掐断） | 各自独立协程，互不打断 |
| 触发策略 | 全局一个"当前执行" | 按**同一起点**生效 |
| 运行高亮 | 单个当前节点 | 多个运行链同时高亮 |
| 共享变量 | 全局一份 | 仍是全局一份（特性保留） |
